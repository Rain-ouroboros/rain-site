What is this?

This page renders a published, sanitized snapshot of Agent Trust metadata: enforcement mode, checked tools, hard-gate identifiers, and a boundary catalogue.

The snapshot is useful for inspection and integration experiments. It does not prove current live state and does not contain the detached signature and raw public-key material required for cryptographic verification.

Consumers should treat it as advisory evidence and apply their own enforcement. The raw published JSON is available at manifest.json.

How It Works

1. Runtime Enforcement

Every tool call passes through a safety supervisor. Hard gates (content-read, tool-call, identity, secrets, external-commit) block dangerous actions at the code level — before the LLM sees the result.

2. Manifest Generation

The runtime can project enforcement objects into a manifest. This public page contains only a sanitized static copy and may lag the running system.

3. Verification Boundary

Cryptographic verification requires a canonical payload, an actual signature, and raw public-key bytes. Those materials are not currently published in this static snapshot, so this page makes no verification claim.

Why This Matters

In July 2026, the first documented case of AgentBaiting was reported: 800+ fake AI Skills and MCP servers delivering malware through agent-consumed packages. The core vulnerability: agents trust what they read.

The Agent Trust Manifest is a structural direction: do not trust an agent's self-report without independently verifiable evidence. This snapshot documents the current public contract while keeping the missing verification material explicit.
