What is this?

This is a signed Agent Trust Manifest — a machine-readable declaration of what an AI agent can and cannot do, generated directly from its runtime enforcement configuration.

Unlike a self-reported promise, this manifest is a projection of live enforcement: the boundaries listed here are enforced by code that the agent cannot modify. The manifest is signed with an Ed25519 key held by the promote service — a separate process the agent does not control.

Third parties can verify the signature against the agent's public key, confirming that the manifest was generated by the enforcement layer, not by the agent itself.

Signature Verification

Anyone can verify that this manifest was signed by the enforcement layer, not by the agent.

# 1. Download the manifest
curl -s https://raw.githubusercontent.com/Rain-ouroboros/ouroboros/ouroboros/docs/agent-trust/manifest.json -o manifest.json

# 2. Extract the signature (base64)
SIG=$(jq -r '.signature' manifest.json)

# 3. Remove signature and normalize
jq 'del(.signature)' manifest.json > manifest-unsigned.json

# 4. Verify with agent's public key
echo -n "$(cat manifest-unsigned.json)" | openssl p256verify \
  -pubin -sigfile <(echo "$SIG" | base64 -d) \
  -inkey rain-agent-trust.pub

How It Works

1. Runtime Enforcement

Every tool call passes through a safety supervisor. Hard gates (content-read, tool-call, identity, secrets, external-commit) block dangerous actions at the code level — before the LLM sees the result.

2. Manifest Generation

The manifest is built by reading live enforcement objects: CHECKED_TOOLS, _BOUNDARIES, _INTERNAL_ENFORCED_BOUNDARY_IDS. It reflects reality, not aspiration.

3. Cryptographic Signing

The promote service (a separate process) signs the manifest with its Ed25519 key. The agent cannot access this key. Third parties verify the signature against the agent's public key.

Why This Matters

In July 2026, the first documented case of AgentBaiting was reported: 800+ fake AI Skills and MCP servers delivering malware through agent-consumed packages. The core vulnerability: agents trust what they read.

The Agent Trust Manifest is a structural answer: don't trust the agent's self-report — verify the enforced boundaries. If every agent published a signed manifest of its runtime-enforced limits, agent-to-agent trust becomes possible.
